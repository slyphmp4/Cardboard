# Cardboard 26.2.5

Cardboard 26.2.5 completes compatibility for modded block inventories that do not have a dedicated CraftBukkit BlockState implementation.

## Fixes

- Exposes unsupported modded block containers through Paper's `BlockInventoryHolder` contract instead of returning a null holder.
- Makes generic `ContainerBridge` owner lookup delegate to the backing `BlockEntity` when available.
- Makes `Inventory#getLocation()` resolve directly from the backing `BlockEntity` for modded block containers.
- Allows CoreProtect 24.0 to recognize Storage Delight cabinets as block-backed inventories and reach its container transaction logging path.
- Keeps vanilla `minecraft:*` BlockState failures strict rather than hiding unrelated CraftBukkit invariant violations.

## Validation target

- Minecraft 26.2
- Fabric Loader 0.19.3
- Storage Delight 26.7.1-26.2-fabric
- CoreProtect 24.0
- JDK 25

This release follows the 26.2.4 crash fix: 26.2.4 prevented `Unexpected BlockState` from aborting inventory events, while 26.2.5 restores the Bukkit holder/location metadata required for container logging.

The release commit is published only after the full Cardboard build, reproducibility check, and torture harness pass on the release candidate.
