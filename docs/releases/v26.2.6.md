# Cardboard 26.2.6

Cardboard 26.2.6 completes the next layer of Bukkit compatibility for arbitrary modded block containers discovered while validating Storage Delight with CoreProtect 24.0.

## Fixes

- Gives generic `ContainerBridge` implementations a real item list by reading every slot from the backing Minecraft `Container` instead of returning `null`.
- Prevents `CraftInventory#getContents()` from failing on Storage Delight inventories that do not have a dedicated Cardboard container mixin.
- Allows unknown non-`minecraft:*` block entities to expose a generic `CraftBlockState` through `Block#getState()`.
- Keeps the strict `Unexpected BlockState` invariant for vanilla `minecraft:*` block entities so actual CraftBukkit factory regressions are not hidden.
- Restores the code paths used by CoreProtect inventory transaction capture and `/co inspect` for Storage Delight cabinets.

## Validation target

- Minecraft 26.2
- Fabric Loader 0.19.3
- Storage Delight 26.7.1-26.2-fabric
- CoreProtect 24.0
- JDK 25

This release follows 26.2.5, which supplied generic `BlockInventoryHolder` and inventory location metadata. Runtime testing of 26.2.5 then exposed the missing generic item-list and block-state behavior addressed here.

Release tag: `v26.2.6`.
