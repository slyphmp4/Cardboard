# Cardboard 26.2.7

Cardboard 26.2.7 fixes a regression exposed by the generic modded `CraftBlockState` fallback added in 26.2.6.

## Fixes

- Keeps `Inventory#getHolder()` non-null for arbitrary modded `BlockEntity` containers even when `Block#getState()` now succeeds with a generic `CraftBlockState`.
- Returns a generic Paper `BlockInventoryHolder` for non-`minecraft:*` `Container` block entities that do not have a dedicated CraftBukkit inventory state wrapper.
- Preserves the real backing block and a live `CraftInventory` over the same Minecraft `Container`.
- Restores the CoreProtect `InventoryClickEvent` gate for Storage Delight cabinets so container transactions are not silently discarded before asynchronous logging begins.
- Retains native `InventoryHolder` states for vanilla and explicitly supported block entities.

## Validation target

- Minecraft 26.2
- Fabric Loader 0.19.3
- Storage Delight 26.7.1-26.2-fabric
- CoreProtect 24.0
- JDK 25

26.2.6 removed the `Unexpected BlockState` and null-contents failures. Runtime testing then showed that the successful generic `CraftBlockState` path bypassed the older exception-based generic holder fallback; this release moves the holder fallback onto the normal successful path as well.

Release tag: `v26.2.7`.
