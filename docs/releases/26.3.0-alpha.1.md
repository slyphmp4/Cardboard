# Cardboard 26.3.0-alpha.1

First experimental Minecraft 26.3 release, based on the maintained Cardboard
26.2.27 fork. Published as a prerelease; the 26.2.27 line retains its stable status.

## Requirements and installation

| Component | Version |
| --- | --- |
| Minecraft | 26.3 |
| Java | 25 or newer |
| Fabric Loader | 0.20.1 or newer |
| Fabric API | 0.166.2+26.3 or a compatible newer 26.3 build |
| Paper API contract | 26.3 build 249 |

Put `Cardboard-26.3.0-alpha.1.jar` in the Fabric server's `mods/` directory
alongside Fabric API. Put Bukkit/Spigot/Paper plugins in `plugins/`.
iCommonLib is bundled. Validate the server's actual plugin/mod pack on a copy
of its world before migrating an existing installation to this alpha.

The release includes `SHA256SUMS.txt`. With both downloaded files in the same
directory, verify the JAR with `sha256sum --check SHA256SUMS.txt`.

## Changes

- Port registry loading/builders, brewing, item components, sign editing,
  particles, entity wrappers and native hooks to Minecraft 26.3. Include
  cushions and poplar boats, and preserve unknown modded item components.
- Restore chunk-state queries, biome reads/writes, ray tracing, line of sight,
  item drops, tree generation, explosions, POI/biome searches and structure
  templates with their callbacks, events and persistent data.
- Restore raid persistent data, native raid/structure lookup and End battle
  API behavior, including controlled native respawn-state tests.
- Implement personal player time/weather, sleep-ignore behavior and world
  view-distance/void settings through native state and packets.
- Restore command aliases and dedicated/integrated restart lifecycles. Provide
  all 37 native Brigadier argument types and 40 public factory overloads.
- Complete game-dialog/custom-click delivery, callback queues, use/expiry and
  replay behavior, typed responses and stop cleanup. Keep registry conversions
  current after reload/world replacement and ignore malformed callback IDs
  without emitting server errors.
- Preserve native client behavior in shared entity/inventory code and verify
  two successive integrated worlds, a separate LAN guest and dedicated
  LuckPerms-Fabric permissions.

## Release verification

Publication requires successful CI on the exact merged release commit and a
byte-for-byte match between the release JAR and its successful CI artifact.
Only the canonical JAR and its checksum file are published.

The full gate includes 13 checks: builds/tests, reproducibility, common plugin
startup, API runtime, 93 API groups before/after full process restart on each
production configuration, three saved-data groups, 69 shared API groups on
checksum-pinned official Paper 26.3 build 249, native owner-client dialog actions,
two integrated worlds, LAN/LuckPerms and three dedicated restart scenarios.

Both stock and checksum-pinned Lithium/FerriteCore/C2ME configurations run a
1,800-second workload and verify their saved world after a complete restart.
Performance mods are test inputs and are not bundled with Cardboard.

## Known limits

- Configuration-phase dialogs and player reconfiguration APIs remain incomplete;
  the tested dialog/callback path uses game connections.
- This is bounded alpha validation, not complete Paper API parity, a six-hour
  soak or a guarantee for arbitrary plugin/mod combinations. Common-plugin
  checks cover startup and selected API/command paths.
- Client fixtures use offline profiles over loopback. Dedicated restart process
  coverage runs on Linux. Controlled End battle tests do not replace full
  player-driven dragon combat/resurrection coverage.
